> ## What happened
>
> PR #658 typed `Axiom` with a `ParamSpec` in commit 181f79d: `class Axiom[**P, T]` with `equation: Callable[Concatenate[type, P], T]` and `def axiom[**P, T](equation: Callable[P, T]) -> Axiom[P, T]` in `discopy/testing.py`. The `docs (3.14)` job then failed:
>
> ```
> Extension error (sphinx.ext.autodoc.typehints):
> Handler <function record_typehints ...> for event 'autodoc-process-signature'
> threw an exception (exception: 'typing.ParamSpec' object has no attribute '__origin__')
> ```
>
> Run: https://github.com/discopy/discopy/actions/runs/34098612446/job/101667702777
>
> Cause: `pyproject.toml` pins `sphinx == 7.2.*` in the `docs` extra and `uv.lock` holds 7.2.6, whose `sphinx.util.typing.stringify_annotation` handles a `TypeVar` but not a `ParamSpec`. It only bites on Python 3.14, which the docs job runs: there `typing.get_type_hints` resolves the PEP 695 type parameter and hands Sphinx the `ParamSpec`; on 3.12 the name does not resolve, Sphinx falls back to the raw string, and the build passes, which is why it was not caught locally.
>
> Stopgap on the PR branch, commit 024f08c: `docs/_ext/paramspec.py`, an extension that renders a `ParamSpec` by its name under Sphinx 7.2, listed in `docs/conf.py`'s `extensions`. Its docstring says it retires when the lock moves to Sphinx 7.4.
>
> Verified facts, on Python 3.14 with a copy of those annotations: Sphinx 7.2.6 crashes as above; Sphinx 7.4.7 renders `Callable[[Concatenate[type, P]], T]` natively with no warning. `sphinx-autodoc-typehints` is not a way out: Sphinx's own `record_typehints` handler still runs and crashes with the plugin loaded, and on 7.4.7 the plugin renders `ParamSpec(P)`/`TypeVar(T)` with forward-reference warnings, worse than Sphinx alone.
>
> Why the lock was not bumped on the PR: regenerating `uv.lock` needs the `download.pytorch.org` index, unreachable from the agent sandbox that made the shim. This task needs an environment where `uv lock` can reach it.
