# Random SAT: one wiring, many policies — Part 1

Part 1 of [`project.md`](project.md): the encoding, the pipeline and the
factor-graph baseline. A random 3-SAT instance becomes a diagram, a
[`MapNN`](../../../../discopy/neural/) interprets it, a solver runs it, and a
per-variable assignment is read off and **checked exactly**. Everything later
in the project builds on this file set; nothing here claims to be a
competitive SAT solver, and the honesty rules of `project.md` are the point,
not a disclaimer.

The difference from [`examples/sudoku`](../sudoku/) is one sentence: there,
one diagram served every puzzle; here, **every instance is its own diagram**.
That is what makes this a test of `discopy.neural`'s central claim — a dataset
of samples whose diagrams all differ, trained by one set of shared weights —
and what makes compilation, not arithmetic, the cost that bounds the study.
[`NOTES.md`](NOTES.md) measures it.

## The encoding

NeuroSAT-style literal splitting, because a wiring carries no per-edge sign
and state is addressed per site, not per port. Each variable becomes **two**
literal nodes and the polarity lives in the graph:

```python
MSG, STATE, CSTATE = Ty("msg"), Ty("state"), Ty("cstate")

literal = Signature((Orbit(MSG, degree, Sym.PERM), Orbit(STATE, traced=True)))
clause  = Signature((Orbit(MSG, size, Sym.PERM), Orbit(CSTATE, traced=True)))
flip    = Signature((Orbit(MSG, 2, Sym.PERM), ))
```

`from_incidence` draws the bipartite factor graph out of the formula's
combinatorics alone: per literal node, the clauses it occurs in **plus the
flip relation of its variable**, with `relation={"clause": …, "flip": …}` and
one name per relation. Three generator names, three shared modules, and a
model whose size is independent of the formula's:

| generator | what it is | module |
|---|---|---|
| `lit` | a literal node, one port per relation it belongs to | `Site`, GRU, **mean** pool |
| `clause` | a clause, one port per member | `Relation`, Deep Sets, sum pool |
| `flip` | a variable, wiring its two literal nodes | `Relation`, arity 2 |

The literal cell pools with a *mean* because literal degrees vary a lot —
Poisson with mean `kα/2 ≈ 6.4` at the threshold — and a mean keeps a cell's
input scale independent of its degree. All three modules serve any degree, so
one `Site` fills every literal site of every instance.

**One wiring, two clause interpretations.** `--stateful` sends `CSTATE` to
`Dim(state_dim)` and fills the clause box with a recurrent `Site` — the
NeuroSAT-faithful variant; the default sends it to `Dim(0)`, which erases the
clause loop and its ports, and fills the box with a stateless `Relation`. The
*diagram* is the same object either way, exactly as models A and C of the
sudoku study share one grid.

## The task layer, which is ours and not the library's

* **No encoder.** The formula is the diagram, so there is nothing to inject:
  the initial state is one learned vector shared by every literal node, plus a
  small Gaussian perturbation — without which every literal of a symmetric
  formula would carry the same belief for ever. The solver runs with
  `inject=False`.
* **Readout.** `read(D, state, ("lit", STATE))` → a linear head → one logit
  per literal node. A variable's probability is that of its **positive**
  literal; that the negative literal disagrees is a measurable residual, used
  as a small auxiliary loss and reported by `model.consistency`.
* **Loss.** Unsupervised smooth-SAT: clause score `1 − ∏(1 − p_l)`, loss
  `−Σ log(score + ε)`, computed in log space throughout. No assignment is
  supervised — a satisfiable formula has many solutions and supervising one of
  them is ill-posed; what the loss asks for is that *every clause* hold, which
  is the actual specification.
* **Decode.** Threshold at `0.5`; an instance is solved iff the rounded
  assignment satisfies every clause. The verifier is exact and free, which is
  the one place this domain is kinder than sudoku — no learned critic is
  needed to know whether an answer is right. `model.decode` is checked against
  the classical verifier in `baselines.py`.

## Data

Uniform random 3-SAT, `n` uniform in `[10, 100]`, `α ∈ {3.0, 3.5, 4.0, 4.26}`,
**filtered to the satisfiable instances**. Satisfiability is *decided*, never
guessed: WalkSAT runs first because a solution it finds is a certificate, and
a counter-based DPLL decides the rest (20–43 ms per instance at the threshold,
where roughly half of what is generated is thrown away). Filtering with an
incomplete solver would quietly remove the hard satisfiable instances, so the
filter is complete and `dataset.py --check` re-decides every instance it kept.

Held-out test sets are one per `(n, α)` on a 5 × 4 grid. Instances with
`n ∈ {150, 200, 300}` are generated by `dataset.load_large` and read by
**nothing** in Part 1 — they are Part 2's size-generalization study, and
keeping them out of reach here is what will make that study honest.

## Solver and protocol

`Iterate(rounds=32, inject=False)` with `deep=True` and the loss averaged over
every round's checkpoint in one backward graph — the sudoku model-A recipe.
Adam, gradient-norm clip 1.0, one optimizer step per batch.

A **pool** is the unit a run is organised in: a set of batches compiled
together, reused for `epochs` passes, then replaced by fresh instances. A
compilation is Python and a step is a fixed number of kernel launches, so this
is the knob that trades instance diversity against wall clock; `Budget` spells
it out and every checkpoint records how many seconds went into drawing,
compiling and stepping. See [`NOTES.md`](NOTES.md).

Metrics, and neither replaces the other:

* **decode rate** — the fraction of instances whose rounded assignment
  satisfies every clause. This is the number the study is about.
* **clause rate** — the mean fraction of clauses satisfied. A model can push
  this to 0.99 with a decode rate of zero, which is exactly the failure a
  per-clause metric hides.

Baselines on the *same* test sets: random assignment, greedy (WalkSAT with
zero noise) and WalkSAT, the two local searches given the per-instance wall
clock the model's message passing spent. The success criterion of `project.md`
is a decode rate materially above greedy at `α ≤ 4.0`, `n ≤ 100`, improving
monotonically with test-time rounds — *not* competitiveness with WalkSAT, and
certainly not with CDCL.

## Results

The instrument runs end to end — data, diagram, training, exact decode,
grid report, baselines and the equivariance check — and the miniature budget
reproduces the whole path in a few minutes. **The recorded baseline run has
not been made yet**, so no decode-rate table is claimed here; the numbers
`train.py`/`evaluate.py` print are the numbers, and they belong in this
section once a `--seed 0` run at the `full` budget has finished.

What is measured and recorded so far is the cost model, in
[`NOTES.md`](NOTES.md): a training pool of 46 807 boxes costs 20 s to draw,
370 s to interpret and 6 s per epoch thereafter, and two behaviour-preserving
changes in `discopy/cmap.py` would make the compile path linear and about 20×
faster. That ratio, rather than the arithmetic, is what bounds how many
distinct instances Part 1 and Part 2 can afford to see.

## Layout

    config.py     paths, widths, budgets, the (n, alpha) grid
    dataset.py    random 3-SAT, the satisfiability filter, splits, caching
    baselines.py  the exact verifier, DPLL, WalkSAT, greedy
    model.py      roles, signatures, combinatorics, readout, loss, decode
    train.py      the pool of compiled batches and the training loop
    evaluate.py   fixed compute, round sweeps, the grid, the baselines

Everything else is `discopy.neural`'s and generic in the task. Data and
checkpoints are written inside this directory, under `data/` and
`artifacts/`.

## Running

    python dataset.py --budget quick --check   # build and verify the data
    python train.py --quick                    # a few-minute miniature
    python train.py --seed 0                   # the recorded baseline
    python train.py --stateful                 # the recurrent clause

    python evaluate.py artifacts/quick-factor-seed0.pt --quick --baselines
    python evaluate.py artifacts/full-factor-seed0.pt --sweep 32 64 128 256

Run them from this directory. One GPU suffices; `MapNN.compile_rounds` is
deliberately **not** used, because a fresh diagram per batch would mean one
`torch.compile` per batch.
